## Bootstrapping note (no repo yet)
The planning step (`/interview`) wrote `docs/roadmap.md` and `docs/plan/*.md` into the plain directory
before any git repo exists. Per `dev-workflow`, the build flow normally "branches first from `HEAD`,"
but there is **no repository yet** — the skill says to stop and confirm with the user in that case.
**Confirmed resolution:** FEATURE-56AA's build runs **`git init -b main` as its first action** — this
is the *sole* repository-state-modifying step the build performs, standing in for the usual branch
creation (there is no `HEAD` to branch from yet), and it works directly on `main` (no separate dev
branch for this bootstrap item). The build then produces all deliverables + this item's completion doc
and **stages** them, but — per the `dev-workflow` rule *"never commit changes yourself; leave all commits
to the user"* — it does **not** run the initial commit: it stops and prints a suggested initial commit
message (scoped `chore`/`docs`) for you to run. Every later item (FEATURE-4442 phases) follows the
normal "branch from `HEAD`" rule (`feature/feature-4442-phaseNN-…`).
